# Plan: Revamp `docs/guide/custom_hooks`

## Motivation

The current section is sparse and hard to follow. Its four pages
([index](../docs/guide/custom_hooks/index.md), [writing](../docs/guide/custom_hooks/writing.md),
[patterns](../docs/guide/custom_hooks/patterns.md), [queue](../docs/guide/custom_hooks/queue.md))
are **all anchored on VMAC** — a templated complex MAC with `m_axi` strides and two csynth gotchas.
`writing.md` throws the reader into that on page one, before a single hook has been shown connecting
to anything.

## Organizing principle

**The three hook patterns differ by who owns the data movement** — and that axis is also the order of
increasing difficulty, so it doubles as the teaching order:

| Pattern | Who moves the data | Hook body | Anchor example |
|---|---|---|---|
| **Block** (load–compute–store) | codegen (auto-gen `read_array`/`write_array` in `run_proc`) | pure compute over materialized C++ arrays | NEW tiny example |
| **Stream** (process-as-you-read) | the hook's lane loop | read loop + compute + write, TLAST/framing | poly ([stream_inband](../examples/stream_inband/poly_evaluate_impl.tpp)) |
| **Complex** (data-dependent addressing) | the datapath itself | `m_axi` strided gather/scatter + datapath | vmac ([vmac](../examples/vmac/vmac_compute_impl.tpp)) |

Scalar precedent for "auto-generated I/O, pure-compute hook":
[regmap/simp_fun](../examples/regmap/simp_fun_compute_impl.cpp) — pure `compute(x,a,b)`, register I/O
auto-generated by the s_axilite path. Block is the **array generalization** of this.

## Capability check (done — informs block.md)

- Codegen does **not** auto-wrap array I/O *inside* a hook call ([hwgen.py:489](../waveflow/build/hwgen.py#L489)
  `_emit_function_call` emits a bare call). Hooks that take a raw port do their own I/O (vmac, poly).
- But the block pattern works **today** by putting `read_array`/`write_array` in the extractable
  `run_proc`/`on_start`, where they auto-generate:
  - [hwgen.py:307](../waveflow/build/hwgen.py#L307) `_emit_mm_array_read` → resident buffer + `read_array_slice`
  - [hwgen.py:328](../waveflow/build/hwgen.py#L328) `_emit_mm_array_write` → `write_array_slice`
  - [hwgen.py:805](../waveflow/build/hwgen.py#L805) `hook_signature` types a `DataArray(cpp_storage='raw')` param/return as `elem[N]`
  - Pattern: `buf = self.mem.read_array(ElemT, n, addr)` → `out = self.compute(buf)` →
    `self.mem.write_array(out, addr)`; `compute` is `@synthesizable(impl_file=…)`, pure compute.
- So block.md presents a **live, do-this-now** pattern. No codegen changes required.
- (Future note: auto-wrapping the load/store *into* the hook call would be new work — a new
  FunctionStmt variant binding array operands to port+addr+count. Out of scope here; mention only as
  a forward pointer if useful.)

### writing.md  (anchor: regmap/simp_fun — the simplest hook)
- The `@synthesizable` stub form: Python body = the bit-exact golden (runs in PySim), C++ hand-written.
- The namespace (`*_impl`), the Python-golden-sibling = bit-exact-by-construction contract.
- The one **general** rule: `#pragma HLS INLINE` (so the hook fuses into the synthesizable top).
- `.cpp` vs `.tpp`: non-templated (simp_fun) → plain `.cpp`; templated (widths) → `.tpp` — forward-ref
  [templating](../docs/guide/comp_codegen/templating.md).
- **Move OUT**: the two VMAC csynth gotchas (scalar `*_core`, nested-struct DCE) → `complex.md`.

### block.md  (anchor: NEW tiny example)
- The pattern: I/O auto-generated in `run_proc` (`read_array`/`write_array`), hook = pure compute over
  materialized C++ arrays. "The array generalization of regmap."
- Show the `run_proc` wrapper (auto-generated `read_array_slice` → call → `write_array_slice`) and the
  pure-compute `.tpp` side by side.
- Introduce `read_array_slice` for the case where the hook *does* touch resident memory.
- When to use: fixed-size operand known up front, no cycle-level streaming needed, random access fine.

### stream.md  (anchor: poly)
- The lane loop walked through [poly_evaluate_impl.tpp](../examples/stream_inband/poly_evaluate_impl.tpp):
  `read_axi4_stream_lane` / `write_axi4_stream_lane`, `pf` lanes, `UNROLL`.
- TLAST / framing, the tail `lane_count = min(nrem, pf)`, the error-status returns.
- When to use: data arrives incrementally / can't or shouldn't materialize the whole burst.

### complex.md  (anchor: vmac)
- `m_axi` + data-dependent addressing: command-driven strides, the `read_array_lane` loop with running
  word pointer, `write_array_lane`.
- **The two VMAC csynth gotchas** (moved here from writing.md, where they finally have context):
  1. scalar `*_core` function (nested struct-by-value DCEs the kernel) —
     [hls-hook-csynth-gotchas memory]
  2. `#pragma HLS INLINE` so `m_axi` binds to the top (already general, but the vmac `elem_to_word`
     helper is the concrete case).
- The complex datapath: `complex_utils` cmult/cadd/conj, `ap_fixed` accumulator, single `cx_requantize`.
- When to use: gather/scatter, strided rows, access pattern depends on runtime command fields.

### queue.md  (keep, light reframe)
