## Motivation

An example's `include/` currently mixes three kinds of file, and nothing on disk says which is which:

| Kind | `markov/include/` instances | Owner |
|---|---|---|
| **Hand-written** kernel bodies | `markov_gen_task.h`, `markov_chain_core_task.h` | the designer (or the agent) — real source |
| **Schema-generated** | `mkv_cmd.h`, `mkv_resp_tb.h`, `uint8_array_utils.h`, `bundle_tb.h` … | codegen from the Python `DataSchema` |
| **Framework copies** | `il_*_task.h`, `mem_*_task.h`, `streamutils*`, `memmgr*.hpp`, `mm_stream_writer_task.h` | copied out of `waveflow/build/` by the build |

`xsi/` has the same mix (framework BFM copies, generated harnesses, and a few authored files), and
generated `.tcl` scripts sit loose at the example root, tracked.

Costs of the mix:

- **Edits get lost or drift.** A framework copy committed in `include/` looks like source. If someone
  edits it, the next build overwrites the change. If nobody rebuilds, it drifts away from the package copy.
- **Agents can't tell what's editable.** Generated headers carry no "do not edit" banner (the
  `<name>_task.h` from `HlsTaskCodegenStep` is the exception). An agent asked to fix a kernel has
  to guess which of 29 files is the kernel.
- **There is no clean build.** You can't delete a directory to start over, because every generated
  directory also holds something authored.
- **The kb index sees noise.** `waveflow/mcp/knowledge/corpus.py` uses `.gitignore` to decide
  what is source, so tracked copies get indexed as if they were examples of hand-written code
  (`examples.py:127` already has to rank `/include/` copies below their originals).

## The rule

> **Every generated directory holds only generated files, is gitignored, and can be deleted and
> rebuilt. Everything authored lives outside them and is tracked.**

There may be several generated directories; they do not need to share one root. Per example:

| Authored, tracked | Generated, ignored, deletable |
|---|---|
| `*.py` (the module, `*_build.py`, `*_xsi.py`, …) | `include/` — schema headers, array utils, framework copies |
| `src/` — hand-written HLS C++ (task bodies, hook impls, example-local headers) and authored XSI C++/Verilog | `gen/` — composite tops `<top>.cpp` **and their `<top>.tcl`** |
| hand-written `.tcl` drivers (`basic_vec/run.tcl`, `regmap/run.tcl`) | `xsi/` — the XSI workspace: framework BFM copies, generated harness / ports / `.f` / dumper, `run.bat`/`run.sh` |
| input data that no step writes | `<top>_proj/`, `logs/`, `results/` (already ignored) |

- Framework headers are never committed into an example. Their one home is `waveflow/build/`.
- Docs figures keep their existing route: rendered into ignored output, promoted to `docs/` by
  `SyncDocsFiguresStep`. The committed copy lives in `docs/`, not the example.
- A drift test that wants to compare generated output regenerates into a temp dir and diffs. It
  never relies on a committed copy (this settles the old open decision on bram_access / mm_fir).

### Why `src/` and not `gen/include/`

An earlier draft considered moving generated headers under `gen/include/` so one directory holds all
build output. That isn't needed: the rule asks only that each generated directory be deletable, not
that there be one. Generated headers going to `include/` is wired into every
`IntField.specialize(include_dir="include")` call, `composite_gen.INCLUDE_DIR` and the TCL `-I` flag
(~180 literal sites). Moving the *hand-written* files instead touches 2–5 files per example. `src/`
is also already the convention in three examples.

## Staleness: what untracking changes

The XSI gates trust `rtl_staleness` (`trace_steps.py:501`) to say whether `<top>_proj/` RTL was built
from the sources on disk. It hashes `gen/<top>.cpp` + `include/*.{h,hpp,cpp}` (`rtl_digest.py`)
against a stamp written at csynth time. Moving and untracking files breaks that guard in four ways,
two of them silent:

1. **An old copy in `include/` hides the real source in `src/` (silent pass).** `gen/<top>.cpp` does
   `#include "markov_gen_task.h"`; with `-Iinclude` searched before `-Isrc`, a leftover copy in
   `include/` wins. Leftovers will exist: `git rm --cached` leaves the file on disk, and every
   copy-step example already has one (`rf_blk_delay/include/blk_delay_task.h` duplicates
   `src/blk_delay_task.h`). Failure: edit `src/`, the guard says stale, re-csynth compiles the old
   copy, the new stamp matches, the gate passes against the old body. A fresh-clone check cannot see
   this, because a fresh clone has no leftovers.
2. **Upstream changes become invisible (silent pass).** The guard hashes the example's *copies*, not
   their origins (`reference-src-shrink-stales-consumer-rtl` memory). Today a commit that changes
   `waveflow/build/memmgr.hpp`, a `DataSchema` or a generator also carries refreshed tracked copies,
   so `git pull` changes `include/` and trips the guard. Once nothing generated is tracked, a pull
   never touches the generated directories, and the guard reports clean against RTL built from old
   framework code. (This hole already exists for the examples whose `include/` is ignored today; the
   plan would extend it to all of them. It is why mm_fir's `.gitignore` tracks `include/` and `gen/`.)
3. **`.tpp` and subdirectories aren't hashed.** `SOURCE_SUFFIXES = (".h", ".hpp", ".cpp")`, but hook
   impls are `{kernel}_{method}_impl.{cpp,tpp}`, and `source_files` uses a flat `iterdir()`.
4. **Existing stamps go stale on rollout (loud, correct).** Examples that already have `src/`
   (rf_blk_delay, bram_access, rf_loopback) will read "`src/… is new`" as soon as the guard hashes
   `src/`, so their gates skip and the `-m xsi` session fails until they are re-synthesized.

S0 fixes 1–3 and budgets for 4.

## Stages

### S0 — Framework: make `src/` first-class, and keep the guard honest

Goal: an example declares nothing beyond putting files in `src/`. No per-example copy step. Generated
directories are safe to delete.

1. **Compile path, `src/` first.** Emit `-Isrc -Iinclude` (in that order) in the csynth TCL
   (`composite_gen.py:2744`, `set cf "-I{INCLUDE_DIR}"`, plus any other `render_tcl` / hand-built TCL
   that sets `-I`). Add `SRC_DIR = "src"` next to `INCLUDE_DIR`. `.cpp` files in `src/` go to
   `add_files` automatically, the way hook impls go through `extra_sources` today. Adding `-Isrc` for
   a directory that doesn't exist must be harmless; verify that on Vitis HLS 2025.1.
2. **Generated `.tcl` into `gen/`.** `render_tcl` callers write `gen/<top>.tcl`. Vitis keeps running
   with the example root as working directory, so `-Isrc -Iinclude` and `<top>_proj/` stay where they
   are. Keep `open_project` a bare name in that working directory (a nested project path drops the
   kernel from csim — `reference-vitis-nested-project-drops-kernel`).
3. **Duplicate-basename check.** A basename present in both `src/` and `include/` (or `src/` and
   `xsi/`) is an error at build time and in `rtl_staleness`. This is the backstop for issue 1 in old
   working trees.
4. **Guard covers `src/`.** In `rtl_digest.py`: hash `src/` recursively (`rglob`), add `.tpp` to
   `SOURCE_SUFFIXES`, and give `src_dir="src"` a **default** in `source_files`, `source_digests`,
   `write_stamp` and `rtl_staleness` rather than threading it through callers. (The
   stamp-only-after-csynth AST lint once found nine call sites a grep had missed; every hand-threaded
   argument is another place to forget.)
5. **Guard sees upstream changes.** Each XSI gate fixture regenerates the example's headers (the
   Python-only codegen DAG — seconds, no toolchain) before calling `rtl_staleness`. The comparison is
   by content, so a no-op regeneration costs nothing, and a pulled change to a framework header, a
   schema or a generator now shows up as a changed `include/` file. Update the `rtl_staleness`
   docstring: the guard is still a predicate, and it still never runs csynth. Rejected alternative:
   have copy steps record where each copy came from and hash those package files in the stamp. That
   is narrower (it misses schema and generator changes) and adds state to every copy step.
6. **Sticky hook stubs.** `HlsTaskCodegenStep.impl_dir` defaults to `output_dir` (= `include/`), and
   its docstring already warns against that. Default it to `src/`. Same for the other
   `impl_dir` in `hwcodegen_steps.py`.
7. **XSI workspace reads authored files from `src/`.** `xsi_workspace.py` / `XsiHarnessStep` compile
   authored XSI sources (mains, helper `.cpp`, hand-written `.v`) from `src/` (or `src/xsi/` —
   decide when the census shows how many there are), and write everything else into `xsi/`.
8. **Lint: nothing tracked under a generated directory.** A test in the ordinary dev loop asserts
   `git ls-files examples/*/{include,gen,xsi}` is empty, apart from an allow-list of examples not yet
   migrated. The allow-list may only shrink; S2 ends with it empty.
9. **Tests first.** Before any example moves:
   - edit a file in `src/` (including a `.tpp`) → the guard reports stale;
   - put a stale same-named header in `include/` → the build refuses;
   - change a framework header in the package → after the fixture's regeneration, the guard reports
     stale.
10. **Delete the per-example copy steps** only as each example migrates (S2), not here.

Gate: the full non-toolchain suite plus `-m vitis` and `-m xsi` pass with no example moved yet,
after re-synthesizing rf_blk_delay, bram_access and rf_loopback (issue 4).

### S2 — Migrate the rest, one example per commit

Order: the ones with copy steps first (each deletes code), then the fully tracked ones, then `xsi/`.

- **Copy-step examples** (fir_block, rf_blk_delay, rf_loopback, rf_relayout, vecmult,
  stream_inband, bram_access, rf_samp_buf_rx/tx): move root-level hand-written files to `src/`
  (rf_blk_delay is already there), delete the `HAND_WRITTEN_TASKS` / `FIXED_TASK_BODIES` copy step,
  and **delete the copy it left in `include/`**.
- **Root-hook examples** (shared_mem, block_scale, state_toy, vmac, regmap): move the hook impls into `src/`.
- **Fully tracked examples** (interleaver, mem_copy, mm_fir): sort each file the same way as in S1.
  mem_copy's per-file `.gitignore` entries collapse to one `include/` line. mm_fir's comment ("tracked
  so the staleness guard has `include/`") goes, because S0.5 covers that reason.
- **bram_access's drift test** (`tests/build/test_wrapper_gen.py`) regenerates into a temp dir and
  diffs, instead of reading committed output.
- **`xsi/`, per example** (the 13 that track it): authored files to `src/`, the rest untracked and
  deleted from disk, `xsi/` ignored.
- **Root `.tcl`**: each generated one is deleted (it now regenerates into `gen/`); hand-written
  drivers stay.

Per commit: the delete-and-rebuild check from S1.4, that example's csynth + XSI cycle count unchanged
(cited in the commit message), and the example removed from the lint's allow-list.

### S3 — Docs, kb, agent guidance

**Where the convention is documented.** It gets one new page, `docs/guide/flows/layout.md`
(*Example directory layout*), a child of *Hardware modules and Flows*, placed after `modules.md`.

*Does the convention differ between the flows?* The **rule** is the same in both: authored files are
tracked, and generated directories are ignored and deletable. What differs is **which hand-written
files a flow has**, so the page gives one rule and then one table per flow:

| | Host-activated (sequential) | Free-running (concurrent) |
|---|---|---|
| hand-written HLS, in `src/` | hook impls `{kernel}_{method}_impl.{cpp,tpp}` | hook impls, plus `kernel_task()` bodies `*_task.h` |
| hand-written, elsewhere in `src/` | — | `rtl_module()` Verilog; authored XSI sources |
| generated, in `gen/` | kernel `.cpp`/`.hpp`, Vitis TB `<kernel>_tb.cpp`, `.tcl` | composite top `<top>.cpp`, `<top>.tcl` |
| generated, in `include/` | schema headers, array utils | schema headers, array utils, framework task copies |
| generated, in `xsi/` | — (Vitis cosim) | harness, ports header, `.f`, framework BFM copies, run scripts |
| verified by | Vitis csim / cosim | XSI gates + staleness guard (which hashes `src/`) |

(Check this table against the code when writing the page; it reflects the census, not a re-read
of every step.) The page also says how to get a clean build: delete the generated directories.

Why `flows/` rather than `patterns/`: `patterns/` describes design *shapes* (command–response,
continuous stream) and does not depend on the flow or the build. A directory layout is a property
of the *realization*, and `flows/` already describes itself as "which build steps run, producing
which artifacts". The layout belongs with the artifacts. `build/` was the other candidate; it is
about the step/DAG machinery, so a reader asking "where do I put my file" would not look there.

Links into it, so a reader finds it from the page where they are writing the file:
- `flows/sequential_flowsteps.md` and `flows/concurrent_flowsteps.md`: one line each, pointing
  to that flow's table.
- `custom_hooks/writing.md:65` (which already says how codegen *finds* the impl file): add
  "it lives in `src/`" plus the link. Do the same in `custom_hooks/body_only.md` and
  `comp_codegen/freerunning_override.md` (`kernel_task()`).
- `build/codegen.md`: "codegen writes into `include/`, `gen/` and `xsi/`; never edit them", plus the link.
- `patterns/command_response.md`: no change. It links to the examples, which will show the layout.

## Open decisions (for the user)

1. **`src/` vs `src/xsi/` for authored XSI files.** Flat is simpler; a subdirectory keeps HLS and
   testbench C++ from sharing an include path. Decide after the S0 census shows how many authored
   XSI files there are.
2. **Banners.** Independently of layout, should every generated file carry a
   `// GENERATED by <step> from <source> — do not edit` line? It's cheap, it helps anyone reading a
   single file, and it makes the census trace mechanical. I'd do it in S0.

## Deferred

- One output root (`out/` holding `include/`, `gen/`, `xsi/`, `*_proj/`). Not needed for the rule,
  and it would touch ~180 `include` + ~180 `gen` + ~100 `_proj` literal sites. Revisit only if the
  set of generated directories keeps growing.
- `examples/_archive/`: leave as-is.
