# Plan: idiom recognition — measure whether agents use the framework's routines, then make them unavoidable

> **Status (2026-10-04): PLAN, nothing built.** Draft for review. Measures before it builds:
> the probes come first so every remedy is judged against a baseline.

## Motivation

AI agents (and students) **transcribe the math instead of recognising the operation**. An FIR
becomes a double loop rather than `np.convolve` / `lfilter`; a stream of int16 samples becomes a
mask-and-shift over 64-bit words rather than a call to the generated serializer. The hand-written
version works, passes the test in front of it, and fails later, somewhere else:

- **Serialization.** Recorded three times in memory: `bram_access` (hand-unpacked a `DataList`),
  `fir_block` (`.range()` lanes), and `mm_fir` on 2026-10-03 (invented a one-int16-per-word wire
  format). Hand-rolled packing is *correct at LW=1*, so no gate fails until a width changes.
- **Timing.** `plans/pipelined_ops.md`: a plain `get()` in a loop simulates with correct data and
  the wrong rate, and *"no user — and no AI agent — has yet found `get_pipelined` without manual
  intervention."*

There are **two different failures**, and they need different fixes:

| Failure | Example | What fixes it |
|---|---|---|
| **Habit** — the agent knows the tool and does not reach for it | numpy: every model knows `np.convolve` | a prompt or a CLAUDE.md line |
| **Discoverability** — the agent cannot know the tool exists | `<stem>_array_utils.h` is generated per element type; there is no stable file to grep | only enforcement: a checker, or an interface where the wrong thing cannot be written |

Prose does not fix the second kind. Two memory notes already said "use the generated serializer",
and the `mm_fir` slip happened anyway.

## What the code says today (census, 2026-10-04)

**Ports carry no payload type.** `StreamIF`, `StreamIFSlave` and `StreamIFMaster` have `bitwidth`,
`has_tlast`, `framed`, `depth`, `queue_size`, and nothing about what flows over them
(`waveflow/hw/interface.py`). Codegen sees only width and framing:
`composite_gen._axis_port` and `StreamEdge` emit `hls::stream<ap_uint<W>>` or the `axi4s_word` /
`framed_word` equivalent.

**Reads choose their mode by method name, writes by argument type.**

- **Reads.** `get(nwords_max=)` returns raw words. `get_schema(T)`, `get_array(T, n)`,
  `get_pipelined(T, n)` and the `_nb` variants are typed. All the typed readers reach
  `super().get(nwords_max=self._typed_nwords(T))`.
- **Writes.** `write`, `offer` and `write_pipelined` each have one `isinstance(data, DataSchema)`
  switch (`interface.py:1331, :1369, :1391`).

**The array path is broken in two places.**

- **Python → C++.** The extractor lowers `get_schema` and `write(schema)`, but
  `_emit_stream_get_array` **raises** (`hwgen.py:221`) and tells the author to write a hook.
- **Hooks.** Lane routines (`read_*_stream_lane`, `read_array_lane`) are generated by
  `arrayutils._gen_lane_helpers` and called **only from hand-written hooks**.

So every array that crosses a stream sends the author into hand-written C++, which is exactly where
the generated routine must be *found*. Raw `get()` has no lowering at all: `StreamGetStmt` with
`inputs=[]` indexes an empty list.

**Python call sites**, outside tests, corpus and generated output:

| Kind | Count | Notes |
|---|---|---|
| Typed reads (`get_schema` / `get_array` / `get_pipelined` / `_nb`) | 54 | the good pattern |
| Raw reads, legitimately schema-blind | 21 | relays, `mem_stream` forwarding, `mm_credit`/`mm_queue`/`mm_regbank`, RF payload-to-BRAM, DAC sink, tokens, a TB capture |
| Raw reads of a **typed** payload, decoded afterwards | 18 | see below |
| Raw writes of `x.serialize(...)` instead of `write(x)` | 16 | `fir_block` (6), `interleaver_inband` (7), `mem_copy` (3) |

The 18 raw reads of typed payloads fall into three groups:

- **Decoded with the canonical serializer, but by hand:** `hist.py:516` is a `get_schema(HistResp)`
  written out longhand, and `fir_block.py:419` and `rf_tx_stream.py:435` are `get_array` written
  out longhand.
- **Decoded with numpy or masks:** `interleaver_inband.py:201,205` (`np.view(np.uint32)`) and the
  credit / progress words in `reverse_stream` and `rf_samp_buf*`.
- **Mixed header + opaque payload in one framed burst:** `rf_shot_tx.py:567`.

**Hand-written C++ hooks:**

- **15 raw `s.read()` of opaque words.** Legitimate.
- **Raw read followed by a generated lane routine** (good): the two `rf_relayout_*`,
  `mm_fir_task.h`, `poly_body_impl.tpp`.
- **One real hand-unpack:** `waveflow/build/rf_tx_loader_task.h:230`,
  `x.range((j+1)*(W/SPW)-1, j*(W/SPW))`. The four other `.range()` sites in `rf_tx_loader` /
  `rf_tx_player` use schema `pack_to_uint` / `unpack_from_uint` and only slice the wide word to the
  struct width.

**Prior art to build on:**

- `AckedStream*` (`reverse_stream.py`) has `status_type`, checked to agree at bind (`:1143`) and
  used to decode (`:886`). This is a typed channel already.
- `CapabilityView` / `as_dir` (`interface.py:129–172`) is a per-binding proxy that restricts
  endpoint methods by direction. This is the restriction mechanism already.
- `SobIF*.element_type` derives `bitwidth` from the type.

## Prerequisite — fix `stream_array_alignment`

`plans/stream_array_alignment.md` (diagnosed, not fixed): for a `DataList` containing a
`DataArray`, the generated C++ and the Python schema pack differently at `word_bw=64`. A probe that
sweeps the width, as the serialization probe below must, would trip on this **framework** bug and
blame the agent. Typed port readers would inherit it.

**Fix it first, or keep the probe's payloads off that shape.**

## Stage 1 — Probes: measure the baseline

Use the blind-test harness (`docs/guide/ai_tooling/blind.md`, `waveflow/mcp/blind_test.py`). Each
probe is a small spec in `examples/mcp_test/`, functional-only like `rotate_func.md`, so a run takes
minutes, not the hours of a full build.

**The design rule: the hidden test varies what hand-written code hard-codes.** Then bit-exactness
alone catches the anti-pattern, with no AI judge. The rotate grader already does this by sweeping
`WORD_BW`.

| Probe | The literal translation | The idiom | The hidden test varies |
|---|---|---|---|
| **serialize** — a header plus an int16 array over a stream | mask / shift / `.range()` | `get_schema`, `get_array`, generated lane routines | word width (32 / 64 / 128) and element width |
| **timing** — a streaming kernel whose pysim must predict RTL cycles | plain `get()` in a loop, or `timeout(constant)` | `get_pipelined` / `write_pipelined`, a declared latency | transaction length (graded against XSI cycle counts) |
| **numpy control** (`--no-waveflow`) — an FIR in Python | a double loop | `np.convolve` / `scipy.signal.lfilter` with `zi` | block length and streaming across blocks (state); runtime as a secondary signal |

Optional later probes:

- **command header** — a `DataList` versus N one-word reads.
- **completion** — `IrqIF` wait versus a polling loop; count register reads in the trace.

**The idiom scan**, added to `summary.md`, is a deterministic report over the files the agent
wrote:

- **Anti-patterns:** `.range(` in C++; shift-and-mask on stream words; `get(nwords_max=1)` in a
  loop; `write(x.serialize(...))`; `timeout(<constant>)` inside a stream loop.
- **Idioms:** `get_schema`, `get_array`, `get_pipelined`, `_array_utils::`, `*_lane<`.

Report counts and file:line. The same scanner becomes the in-loop checker in Stage 2.

**Classify every failure as habit or discoverability.** `summary.md` already lists the guide pages
the agent read:

- **Read `arrayutils.md` (or `serialization.md`) and still hand-rolled:** habit.
- **Never reached it:** discoverability.

Record both per run.

**Statistics.** Agents are stochastic, so run **3–5 runs per arm**. Report the idiom rate and the
pass rate, never a single run.

**Arms**, one per remedy, run against the same spec:

- **A0** — today.
- **A1** — knowledge only: a search-index / guide fix so that `waveflow_search` for
  "pack", "unpack", "int16 in a word", "lane" returns `arrayutils.md`.
- **A2** — the Stage 2 checker.
- **A3** — the Stage 3 typed ports.

**Exit:** A0 baselines for serialize and timing, the numpy control run, and one recorded verdict on
whether A0's failures are mostly habit or mostly discoverability.

## Stage 2 — Checker: push the pointer to the agent at the moment of the mistake

The Stage 1 scanner runs as a **Claude Code hook after Edit / Write**. When the agent writes an
anti-pattern into a Waveflow design, it immediately sees a short message naming the generated
routine for that element type. For example, *"this hand-unpacks int16 lanes; use
`int16_array_utils::read_array_lane<64>`"*. The routine name is computed from the schema when it
can be.

- **Ship it.** It goes with the blind-test harness (configured into the trial folder's settings)
  and with the scaffold `waveflow_new_accel_project`, so a student's agent gets it too.
- **Rejected for now: an AI checker.** It needs an AI only for judgement calls, such as a mask that
  is real bit-field work. Add it only if Stage 1 shows the regex's false-positive rate is a problem.

**Exit:** re-run the probes as arm A2.

## Stage 3 — Typed payload ports: make the wrong thing hard to write

A stream port declares the **set** of payload types it carries. A single type is too strict, because
`poly`'s `s_in` carries a `PolyCmdHdr` and then `Float32` samples:

```python
self.s_in = StreamIFSlave(bitwidth=in_bw, payloads=(PolyCmdHdr, Lane(Float32)))
```

**Python.**

- **Reads.** `get_schema`, `get_array` and `get_pipelined` check their type against the set. They
  share one new helper, `_check_payload(T)`, and the `_nb` variants inherit it by delegation. On a
  mismatch the error **names the allowed calls**.
- **Writes.** The three `isinstance` switches check `type(data)`; for a `DataArray`, the check uses
  its element type.
- **Raw `get()` on a typed port is refused** unless `Words` is in the set. `Words` is the explicit,
  greppable escape hatch.
- **Ports with no `payloads=` behave exactly as today.** Adoption is per port.

**Bind** checks that master and slave declare the same set, as `AckedStream` already does for
`status_type`.

**C++.** Codegen emits a per-port reader/writer wrapper with exactly the declared forms, so the
routine is a method on the port the author already holds rather than something to find. For
`poly`'s `s_in`, roughly:

- `read_PolyCmdHdr(s)`
- `read_lane(s, float out[pf])`
- `decode_PolyCmdHdr(const ap_uint<W>* buf)` and `decode_lane(const ap_uint<W>& w, float out[pf])`
  — the buffer-decode forms. These are required: `mm_fir_task.h` reads word by word with `read_nb`
  at II=1, dispatching HDR / CFG / SAMP by state, and decodes from a word buffer, not with the
  stream readers.

**Lower `get_array` in the extractor** for a declared `Lane(T)`, closing the `hwgen.py:221`
refusal. Then an array crossing a stream no longer forces a hand-written hook.

**Migration** is driven by the census:

- **Declare `Words`:** the 21 legitimate raw reads.
- **Convert to the typed call:** the 18 raw reads of typed payloads. `hist.py:516`,
  `fir_block.py:419` and `rf_tx_stream.py:435` are mechanical.
- **Convert to `write(x)`:** the 16 raw writes.
- **Fix the one C++ hand-unpack** (`rf_tx_loader_task.h:230`).

Every recorded cycle count and XSI gate must stay identical. That is the proof the migration was
behaviour-neutral.

**Exit:** re-run the probes as arm A3, and compare A0–A3.

## Decisions for review

- **D1 — Stage order.** Recommended: Stage 1 before any fix, so each remedy is measured.
  Alternative: build Stage 3 first because it is clearly right, and accept no baseline.
- **D2 — The prerequisite.** Fix `stream_array_alignment` first (recommended), or design the
  serialize probe around it.
- **D3 — The ordering rule.** Should a port also declare *order* ("a header, then `hdr.n` lanes"),
  which pysim could check at runtime? Recommended: **not now**. The set gets most of the value;
  ordering is a framing grammar and a much bigger design.
- **D4 — Where `payloads=` lives.** On the `StreamIF` (one declaration, both ends inherit it) or on
  each endpoint (checked at bind). Recommended: on the endpoint, matching `status_type`, because
  ports are declared on modules before any interface exists.
- **D5 — The timing probe's grader.** XSI cycle counts need a csynth per run, so the grader runs
  Vitis. Accept that, or grade timing against a reference pysim instead (cheaper, but weaker).
