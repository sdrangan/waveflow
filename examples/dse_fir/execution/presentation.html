03 / Observations

The same call produces useful evidence for both designs

Two settings per design; repeat the second. All six Python evaluations completed.

What this establishes: one execution interface can carry design-specific quality, correctness checks and modeled timing without putting those meanings in the caller.

The repeated settings reproduced the reported metrics. These are two-point demonstrations—not a search for the optimum or evidence that an agent improves DSE.

Say: “For FIR, rejection increased from about 27 to 55 dB when I changed the tap count. For MemCopy, both widths copied the data correctly, and the wider bus reduced modeled simulation end time from 602 to 341 cycles. The contribution here is the common execution path; these are not hardware speedup measurements.”

Appendix · method, evidence and reproduction

Scope of the demonstration

The demo used predetermined candidates, not an autonomous search. Discovery and Python execution work through the service, CLI and actual stdio MCP. Synthesis returns an explicit unavailable outcome. RTL evaluation cannot proceed without a successful bound synthesis artifact.

Conditions and metric definitions

  • FIR: 1,024 samples; 2,048-point frequency analysis; seed 0; input peak 0.5; passband edge 0.20 and stopband edge 0.28 in normalized frequency. Candidates used 8/32 taps, 16-bit samples, two integer bits, a 32-bit memory bus and no lane unrolling.
  • Stopband rejection: 10 log₁₀(stopband input power × mean passband magnitude² / output AC power). It is a signal-domain quality measure, distinct from the worst-bin frequency-response attenuation.
  • MemCopy: four jobs × 512 bytes = 2,048 bytes per run. Each run checked copied data and the count of four completion bursts. Echoed completion IDs and RTL equivalence were not checked.
  • Model cycles: SimPy simulation end time expressed at a 100 MHz reference clock. The model is uncalibrated; the value is not last-completion latency or achieved hardware timing.
  • Repetition: the 32-tap and 64-bit settings were each executed twice, with the same request identity but distinct attempts. This is a repeatability check, not a statistical study.

Why wall time is not in the main results

Execution wall time includes first-use imports. The sequence was not designed to estimate runtime differences, so presenting those durations as speedups would be misleading.
