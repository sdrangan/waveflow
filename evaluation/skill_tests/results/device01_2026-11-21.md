## How the runs went

- **The MCP arms stopped after their Stage 1** (schemas, golden, `DESIGN.md`): the `bus_system` frame's
  process says to stop for review even in an unattended session. Each was resumed once with
  *"Approved. Continue."* (`waveflow blind-test --resume --message ...`), as a student would. Their
  turns and tokens below are both phases together. **No skill run stopped**: each said it took
  "write the code" as the approval.
- **Three skill versions were run.**
  - **v1** (the skill as committed, `e0d1736b`) pointed to a worked trial under
    `evaluation/skill_tests/results/vmul_2026-11-21/`. Both v1 runs followed it into the checkout; the
    Sonnet run listed `evaluation/skill_tests/` and so saw the reference answer's file names (its own
    files then had the same names). Neither opened the answers. **Both v1 runs are discarded**; the
    pointer was replaced by the `memcpy` example, and `test_no_skill_points_into_the_evaluation_folder`
    now guards every skill.
  - **v2** (the pointer removed): both runs at 48; both missed D3 and D4.
  - **v3** (two lines added to the self-check, below): both at 50.

**Sonnet MCP, the one run well below the ceiling.** Beyond the items above it chose to keep the
output's spare lanes by a **read-modify-write** of the last word (an extra read per job, and a race
between two in-flight jobs whose buffers share a word, which it stated). Legitimate, stated, and
heavier than the whole-word rule the skill gives. The skill runs all wrote whole words and said so.

**Opus MCP** reached 49 by redesigning at Stage 2: its Stage 1 plan relayed the descriptor through the
reader and answered an error with a zero-length read, which pysim refused (`nwords must be a positive
integer`); it moved the descriptor to its own stream. The skill states that rule up front (rule 2).

## What it shows

- **The skill lifts Sonnet from 44 to 50 and holds Opus at the ceiling.** The items Sonnet MCP lost are
  the skill's own rules: words counted by the schema, no `len=0` read, the harness, the word "device".
- **Turns and tokens: no consistent saving here**, unlike the first three skills. Opus: -33% turns,
  -32% tokens in, -32% out (v3 against MCP). Sonnet: about even (57 against 56 turns, +10% tokens in).
  The MCP arms' resume reloads the context once, which inflates their input tokens.
- **The skill arms skip the frame's review stop.** All four skill runs (v2, v3) and both MCP system
  runs went straight through; all four MCP device and pipeline runs stopped. Whether a skill should
  restate the stop is a question for the frames process, not answered here.
