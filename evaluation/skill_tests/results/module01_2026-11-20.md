**B5, the window at a frame boundary.** "New values apply from the next frame that starts after they
are written." A check before blocking on the next frame leaves a window: a commit during the wait
applies a frame late. The reference had it unstated. The runs:

- Sonnet skill: polls both streams once a clock, settings first (`get_schema_nb`, `get_nb`), the
  `read_nb`-on-both loop an HLS body would use. Exact.
- Opus MCP: `begin_read(pending_ok=True)`, the frame's first word, then drains the settings. Exact,
  through a public method the guide does not document.
- Opus skill: the check before the wait, and the window **stated**, with why it did not use
  `begin_read` (not in the guide).
- Sonnet MCP: exact, by reading `s_cfg.burst_stamps` and `data_buffer`, pysim internals it calls "not a
  public API". 1.

The sheet's B5 and the reference's `DESIGN.md` were corrected to this after the runs.

## What it shows

- **All four at or near the ceiling (49-52 of 52).** As with the first two skills, the MCP server
  already gets both models there: the frames process and `mm_fir` carry the mapping. The skill's
  measurable effect is on the cost: turns -13% (Opus) and -44% (Sonnet), output tokens -9% and -18%,
  input tokens -29% and -37%.
- **The one item the skill alone teaches is A3**, stating an open choice with its alternative: both
  skill runs did, neither MCP run did.
- **The test's hardest trap was one the spec did not plan** (B5's window), and three of four handled
  it better than the reference.

## Changes made after the runs

- Skill rule 6: a check before a blocking wait leaves a window; loop on both streams, or state it.
- Skill rule 5: a complex sample is one `ComplexField` element (`schema/python/complex.md`).
- Sheet B5 and the reference `DESIGN.md`: the window.
- `check_blocks.py`: a plain `HwModule` (the runs' host models) is not flagged for non-stream ports.

## Waveflow gaps found

- **No documented first-word check in pysim.** A module that must act at the moment a burst begins
  (a setting from "the next frame that starts") has `begin_read(pending_ok=True)` in
  `waveflow/hw/interface.py`, which no guide page mentions, or a per-clock poll. Either document
  `begin_read` as the pysim twin of checking `!empty()` before a frame, or add a documented `empty()`.
- **A register bank raises no interrupt** (Opus, both arms, noted it): the command-response pattern's
  "status register with an interrupt on an error" cannot be built; known, in `slave.md`'s list.
