# Reference plan: 01 16-QAM soft demapper

What a good plan for [01_qam16_llr.md](../01_qam16_llr.md) looks like, written from the tree as of
2026-10-17 (main after PR #284: `stream_kernel` on the protocol of `plans/guide_system_first.md` D9).
It is the answer key, never shown to an agent: no spec links this directory.  It is rough by intent --
the scoring section says what must be there, what may differ, and what counts against a plan.

## 1. Approach

- **Reference: `stream_kernel`** -- the same shape exactly: a free-running kernel, a command and its
  samples on `s_in`, the results headed by `Resp(tx_id, nsamp)` on `m_out`, a `Status` per command on
  `m_status`, an early TLAST fatal (`static bool halted`), the testbench generated by `harness`.
- **Pattern:** `docs/guide/patterns/command_response.md`.
- **Departures it should name:** fixed point instead of float32 (`FixedField`, `ComplexField`); a build
  parameter `WORD_BW` with `PF` lanes a word (poly is 32 bits, one sample a word); four outputs per
  sample packed into one 32-bit entry.
- Frame: today the menu's one-kernel frame is `stream_inband` (host-launched, `SeqTB`, cosim) -- the
  wrong architecture for a free-running kernel; a plan that follows it is wrong.  After Stage 4 the
  expected frame is `stream_kernel`.

## 3. Interfaces and messages

- **Types:** `invnoise` a `FixedField` (unsigned, 16 bits, 8 integer); a sample a `ComplexField` of
  `FixedField(16, 8)` (signed); an LLR a `FixedField(8, 6)` with `q_mode=AP_RND`, `o_mode=AP_SAT` --
  `docs/guide/schema/python/fixpoint.md`, `docs/guide/schema/python/complex.md`.  The LLR entry: a
  `DataArray` of four LLRs, or a `DataList` of four fields -- 32 bits either way.
- **`s_in`:** `Cmd(DataList)` -- `tx_id` U16, `nsamp` U16, `invnoise`; one burst.  The samples: an array
  of complex values, `PF` to a word, through the generated array routines (`ArrayUtilsStep`); one burst.
- **`m_llr`:** `Resp(DataList)` -- `tx_id`, `nsamp` -- its own burst; then the entries, `PF` a word, one
  burst (framed as `s_in`, as `stream_kernel`'s `m_out`).
- **`m_status`:** `Status(DataList)` -- `tx_id` U16, `status` an `EnumField` (OK, TLAST_EARLY).
- Each layout given at each width; unused lanes zero.

## 4. Verification

- **The golden:** pure functions: `Ls`, `La` exact (rationals, or integers in units of 2^-8), the product
  with `invnoise` exact, then one quantization -- either `FixedField`'s own `quantize` with `AP_RND` /
  `AP_SAT` (the better answer: the model's rounding is the framework's, checked bit-exact against
  Vitis by its conformance harness), or integer arithmetic with the rule written out.  The four worked
  examples as unit tests; `expected(cmds)` from the intents (the `stream_kernel` shape: `Cmd` intents,
  `stimulus`, `expected`, `default_cmds`).
- **The Python model:** `run_iter` -- read `Cmd`, write `Resp`, the samples through a pipelined
  `TimedPhase` (`load=get_array`, `store=write_array`), the status, `yield self.event()` after an error.
  The compute on the whole array at once (vectorized, `.val`), not a Python loop per sample.
- **The system:** `harness(Qam16Llr, workload=...)` -- the kernel as DUT, a driver and two sinks.  Not a
  hand-written testbench, not `GraphSystem`, not `SeqTB`.
- **The scenarios:** `workload(kind)`; all nine, at each `WORD_BW`.  Scenario 7 (the error mid-sequence)
  checked by the recordings: nothing after the error's status.
- **The build:** codegen (`DataSchemaStep` per schema, `ArrayUtilsStep` for the sample and entry types at
  each width, `StreamUtilsStep`, the top), then `add_system_steps` per width -- `csynth`, `system_rtl`,
  `scenario`, `pysim`, `system_xsi`, `compare` -- on `run_dag_cli`.  Starts from
  `example:stream_kernel/stream_kernel_build.py::build_dag`.
- **The HLS body:** one word per iteration at II=1 with the lanes unrolled (the lane loop,
  `docs/guide/vectorization/hls/loop_optimization.md`); the arithmetic in `ap_fixed` types generated
  from the schemas, the exact intermediates wide enough (`Ls` up to 8·(|y|+1) ≈ 1032, times `invnoise`
  < 256: about 20 integer bits and 16 fractional), one `ap_fixed<8,6,AP_RND,AP_SAT>` assignment at the
  end; the `halted` flag.
- **Throughput:** `PF` samples a cycle -- from the RTL run's cycle count for scenario 9, or a calibrated
  timed phase (`add_calib_steps`); the fill should be `nwords - 1`.

## 5. Gaps a good plan reports

- Whether the generated array routines handle a `ComplexField` of `FixedField` and a four-LLR entry at
  every width (they should; a plan that checks is careful).
- The exact width of the intermediate (a reasoned number, not "wide enough").

## Scoring

**Must have** (each missing item is a fault):

1. `FreeRunMod` with framed stream ports -- not `HostActivated`, not a register map, not `SeqTB`.
2. `WORD_BW` as a build parameter; `PF = WORD_BW / 32` lanes a word.
3. `FixedField` (and `ComplexField`) for the formats, with `AP_RND` / `AP_SAT` named for the LLRs.
4. The three messages as schemas, the boundary fields and widths exact, each layout given.
5. An independent golden with the worked examples; expected outputs from intents.
6. The testbench from `harness`; the build through `add_system_steps` to `compare`.
7. A hand-written HLS body through `kernel_task()`, one word per iteration, the lanes unrolled, citing
   the loop optimization page.
8. The fatal error: the short burst, its status, the kernel stopped -- in the model, the body and the gate.

**Accept either:** a `DataArray` or a `DataList` for the entry; the golden via `FixedField` or written-out
integer arithmetic; throughput by timed phase or by cycle count.

**Counts against a plan:** packing or unpacking words by hand (`feedback-datalist-not-manual-unpack`);
`ap_fixed` types declared by hand rather than generated from schemas; a Python loop per sample in the
model; `SeqTB` or cosim as a gate; a hand-written testbench where `harness` does it; a citation that does
not resolve; an error answered and then carried on from.

**Recorded, not scored:** the frame chosen and what led there; whether `stream_kernel` was found, and
how (cards, search, the menu); whether `FixedField` was found; pages read and never reached; tokens and
tool calls.
