`plans/guide_system_first.md` Stage 1.  The tree: `main` after PR #284 -- `stream_kernel` on the D9
protocol, the guide and the MCP frames **not yet restructured** (the menu's frames: `stream_inband`,
`freerun_pipeline`, `bus_system`).  Model `claude-opus-5-5` (Claude Code default), one run per spec
(the second runs are still to do).  Each run: `waveflow blind-test --prompt <spec> --no-approve

graded with `plan_grader.py` and read against `answers/<spec>.reference.md`.

## Rung 1: 16-QAM soft demapper (`01_qam16_llr`)

| | |
|---|---|
| cost | 52 turns, 5.6 min, 2.6M tokens in (2.4M cached), 35k out |
| choice | `list_frames` then `list_examples`; **no frame** (it rejected all three, each for the right reason: `stream_inband` is host-launched with a register map); the generic process; references `stream_kernel` (primary), `vecmult` (an `HwParam` width), `markov` (several harness systems in one DAG) |
| citations | 40 of 40 resolve (after the grader learned the repo-relative form `example:<name>/examples/<dir>/<file>`) |
| reading | 23 doc pages, 7 example files, 8 searches; first write at tool call 50 of 51 -- it read everything first |
| rating | **would build, with small fixes**; every must-have of the reference plan present |

What it got right, unprompted: `FreeRunMod` with framed ports; `harness` for the testbench (no
hand-written one); `FixedField` / `ComplexField` with `AP_RND` / `AP_SAT`; the D9 header, status stream,
`halted` flag and `yield self.event()`, all from the example; exact intermediate widths reasoned
(`fixed<20,12>`, product `fixed<37,21>`); a golden in stored integers, independent of `fixpoint`, the
worked examples checked by hand; the lane loop; throughput from the testbench's per-word cycle stamps,
with the traced VCD as the fallback.

What it found that we did not know -- **its gaps, each real**:

- **G1, a spec error (fixed):** an early TLAST in the middle of a word at `PF > 1` cannot be seen -- the
  lane routines carry no lane count (no TKEEP), and a zero-padded lane is a legal sample -- so "the `k`
  entries that arrived" could not be implemented.  Rungs 1, 2 and 3 now define an early TLAST per whole
  word.  Framework note: nothing documents TKEEP or a partial last word through the lane routines.
- **G2:** `ArrayUtilsStep` with a `DataList` element -- the build page says "a scalar element type", the
  serialization page says composites pack flat; no example does it.
- **G3:** one class at several widths -- `param_supports` is documented, no example uses it; the plan
  used a thin subclass per width.
- **G4:** 128-bit words -- `serialize(word_bw=128)` returns 2-D `uint64`; the reference's `stimulus`
  assumes 1-D.
- **G5:** where the harness's recordings and per-word cycle stamps land is documented only in outline.
- **G6:** there is no pysim-against-golden step in the framework; the reference checks it in pytest.

What the restructure should take from it: an agent with no frame found the right example from the
cards and followed it closely -- the example carried the protocol, the harness and the stop.  The
frame menu offered it nothing (three frames, none right); a `stream_kernel` frame would have saved the
three rejections, not changed the result.  The docs it needed and found were all reference pages
(schema, vectorization, build), reached by search: the per-page context matters more than nav order.

## Rung 2: block equalizer (`02_block_eq`)

| | |
|---|---|
| cost | 35 turns, 8.9 min, 2.2M tokens in (2.0M cached), 49k out |
| choice | `list_frames`, `list_examples`; fetched `freerun_pipeline`'s process, combined it with `stream_kernel`; references `stream_kernel`, `firblock` (a stage framing a descriptor), `mm_fir` (two inputs agreeing by headers), `interleaver`, `bram_access` (a token stream back between tasks) |
| citations | 56 of 56 resolve |
| reading | 13 doc pages; first write at tool call 33 of 34; it did **not** read `loop_optimization.md` (it said so, and deferred it) |
| rating | **would build, with fixes**; every must-have present |

What it got right: a composite of `EqGain` and `EqApply` with **`harness` on each** and then on the
composite; the exact float order with no fused multiply-add (it rejected numpy `complex64 *` and C++
`std::complex` for that reason, and checked `complexfield.cmult`'s float form); the divider's rounding
and **subnormal flushing in the Vitis float cores** flagged as bit-exactness risks to report, not work
around; the gain-to-apply link header carrying `nvalid` and the error `code`, so the last stage answers;
a token stream back from `apply` to `gain` (the `bram_access` pattern) to make "stops taking both
inputs" true -- and it said that if the spec meant less, the token could go.

What it found -- **three spec errors (fixed)**:

- scenario 1 said "three rows of one or two symbols", but `m` is per command: impossible.  Now
  `nrows = 3, m = 2`, a sixth worked value added;
- `BAD_NOISE` at row 0 was undefined (the header? an empty burst cannot exist).  Now: the header, no
  results burst;
- two errors in one command had no precedence.  Now: `MISMATCH`, then the earlier cut in row order,
  `BAD_NOISE` at a tie.

And one requirement made explicit: the kernel stops answering and stops reading symbols; `gain` may
have read ahead on `s_est` (no back-link required).

Its framework findings:

- **A stage's hand-written body cannot be RTL-harnessed alone**: inside a composite its ports are
  `framed_word<W>`, as a top `axi4s_word<W>`, and `KernelTask` has no way to template the body on the
  word type.  So per-stage harnesses are pysim only.  A real gap for unit-testing composite children.
- Leaf boundary ports are `FramedStreamIF*`; composite children use `StreamIF*(has_tlast=...)` -- two
  idioms for one thing, and nothing says which a composite's boundary child should use.
- `ComplexField` as a field of a `DataList`, and lane routines for a `DataList` element: no example
  (rung 1's G2 again).
- One class at two widths with one `cpp_kernel_name` (rung 1's G3 again).
- `compare` covers sinks only; input consumption ("stops taking") is invisible to it.

## Rung 3: peak detector (`03_peak_detect`)

| | |
|---|---|
| cost | 48 turns, 7.2 min, 2.6M tokens in (2.4M cached), 40k out |
| choice | `list_frames`, `list_examples`; fetched the `freerun_pipeline` process, then rejected it (it fixes memory adaptors; this kernel has none) and followed the generic process; references `stream_kernel` (primary), `firblock` and `memcpy` (the composite form), the pattern page's variable-length section |
| citations | 51 of 53 resolve; the two misses guessed auto-slugs for headings that carry explicit ids (`{#running-it}`, `{#graph-system}`) |
| reading | 22 doc pages; first write at tool call 46 of 47 |
| rating | **would build, with small fixes**; every must-have present, including the main probe |

What it got right: a composite of two leaf `FreeRunMod`s; **`harness` on each stage alone** (`Detect`
against a lane-scan twin, `Serialize` from hand-made wide messages) and then on the composite; a
one-wide-word link message (`WideMsg<PF>`, scalars only so it is one word, 106/154/250 bits) with its
depth reasoned against the sparse density; tag-first `DataList`s for `m_det` with the type always in the
low 16 bits of a message's first word; the lane chain broken as the loop-optimization page says
(compares in parallel first, then a chain of bits and small counters), with a register-stage fallback;
`serialize` holding one message back so TLAST lands right; dense throughput predicted at 0.5 metrics a
cycle at every width, limited by `m_det`, with message sharing as the one lever.

Its gaps, each real:

- **A Python framed write cannot leave TLAST low** -- one `write` is one burst.  Hit by `stream_kernel`
  too (its header is its own burst for this reason).  The plan writes a command's messages as one burst
  at `close` (same words and TLAST, coarser pysim timing).  Framework gap.
- **`DataUnion` rejected**, for the documentation's "ids must be positive" (wrong: `SchemaRegistry.register`
  accepts 0 -- fix the page) and because its generated C++ has no AXI4-Stream methods (true: only
  `read_array` / `write_array`).  If tagged unions are the pattern for variable-length output
  (D9), `DataUnion` needs stream methods -- or the pattern page should say "tag-first `DataList`s".
- **`harness` around a composite** is in no example (the guide says a unit can be a composite).
- **No timed-phase pattern for a data-dependent rate** (`timeout`, `pipeline`, `produce` do not fit).
- `accept_bundle` (input acceptance cycles) is mentioned in a doc and used by no example.
- One `DataList` at several shapes (per `PF`) in one build: no example; it used three classes.
- The early-TLAST-in-a-word ambiguity (the same as rung 1's G1; the spec is now fixed).
