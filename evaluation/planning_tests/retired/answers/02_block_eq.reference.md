# Reference plan: 02 block equalizer

What a good plan for [02_block_eq.md](../02_block_eq.md) looks like, written from the tree as of
2026-10-17 (main after PR #284).  The answer key, never shown to an agent.  Rough by intent.

## 1. Approach

- **References:** `stream_kernel` for a free-running module on framed streams with the D9 protocol (a
  header on the data, a status stream, fatal errors) and its harness; `interleaver` (or `memcpy`) for a
  **composite** of free-running stages joined by internal streams; `patterns/command_response.md`, the
  pipeline form (the command travels with the data, the last stage answers).
- **Departures it should name:** two input streams that must agree (no reference joins two command
  streams); two stages at different rates (once per row, once per symbol); a division; complex float32.
- Frame: none fits today; after Stage 4, `freerun_pipeline` or `stream_kernel` depending on the ladder.

## 3. Interfaces and messages

- **Types:** a complex float32 -- `ComplexField` of float32 (`docs/guide/schema/python/complex.md`) or a
  `DataList` of two `FloatField`s; `N` a float32.
- **`s_est`:** `Cmd(DataList)` (`tx_id`, `nrows`, `m`); the estimates an array of `Est(DataList)` (`h`,
  `N`: 96 bits) -- or two arrays.  **`s_sym`:** `SymHdr` (same fields), then complex symbols, `PF` a
  word.  **`m_out`:** `Resp` (`tx_id`, `nrows`, `m`), then results.  **`m_status`:** `Status` (`tx_id`,
  an `EnumField` of OK / TLAST_EARLY / MISMATCH / BAD_NOISE).
- **The link `gain -> apply`:** the command (so `apply` can check the symbol header against it), then
  per row `g[i]` (a complex float32) -- and an error from `gain` (`BAD_NOISE` at row `i`, or its input
  ending early) carried in it, so the last stage answers.  Depth: a few rows; `gain` runs ahead by at
  most its buffer.  Several layouts are right; the plan must give one.

## 4. Verification

- **The golden:** pure numpy float32 functions in exactly the spec's operation order (each product its
  own `np.float32` operation; no fused or vectorized reductions that reorder); the worked examples bit
  for bit, signed zeros included; `expected(cmds)` from intents; errors stop the expected outputs.
- **Each stage alone, then the composite:** `harness(Gain)` against a per-row golden; `harness(Apply)`
  driven by hand-made link messages and symbols (including a mismatched header); `harness(BlockEq)` at
  the boundary.  The per-stage harness is the probe.
- **The Python model:** `Gain.run_iter`: command, then the estimates, `g` per row (vectorized over the
  rows is fine), the link messages; `Apply.run_iter`: link command and symbol header compared, then per
  row a pipelined phase over `m` symbols; status; `yield self.event()` after an error.
- **The build:** codegen (schemas, array utils for the complex type at each width), `add_system_steps`
  per width and per harness, to `compare`.
- **The HLS bodies:** `Gain` -- sequential per row (the divider's latency is the cost; a pipelined loop
  over rows for scenario 3 is the better answer); `Apply` -- one word per iteration at II=1, the lanes
  unrolled, `g` held for the row; every float operation its own statement (no fused multiply-add,
  `poly`'s Horner rule); the float divider's rounding matching numpy's (IEEE, correctly rounded) --
  a plan that flags it as a thing to check is careful.
- **Throughput:** scenario 10 at `PF` symbols a cycle; scenario 3 limited by `gain`'s per-row latency
  (or its interval, if pipelined) -- ideally estimated beforehand.

## 5. Gaps a good plan reports

- The float divider's bit-exactness against numpy (expected to hold: IEEE division is correctly
  rounded; to be confirmed at RTL).
- Signed zeros through the generated array routines and the BFM (bits, not values).
- Subnormal flushing in the Vitis float cores against an IEEE golden.
- How a free-running module stops after a fatal error -- answered by `stream_kernel` (a `static bool
  halted`; `yield self.event()`); a plan that cites it is right.

## Scoring

**Must have:**

1. A composite of two leaf `FreeRunMod`s with an internal stream; `WORD_BW` a build parameter.
2. Schemas for every message, the link included; the boundary fields exact; layouts given.
3. A golden in the exact operation order, bit-exact on the worked examples, signed zeros included.
4. `harness` for the testbench; the build through `add_system_steps` to `compare`.
5. Hand-written HLS bodies through `kernel_task()`; the no-fused-multiply-add rule; the loop optimization
   page cited.
6. All three errors, fatal, with what each writes before stopping.
7. Throughput for scenarios 10 and 3, with what limits 3.

**Accept either:** `ComplexField` or a two-float `DataList`; one or two arrays for the estimates; `gain`
sequential or pipelined over rows (with its consequence for scenario 3 stated); a token back from
`apply` to `gain`, or none (the spec now lets `gain` read ahead); per-stage harnesses at RTL through
`KernelTask(framed=(...))` (the better answer: one body, its word types supplied where it sits) or in
pysim only; one root per width or a subclass per
width.

**Counts against a plan:** hand packing; `SeqTB` or cosim; a hand-written testbench; a single kernel
doing both stages; an error answered and then carried on from; a citation that does not resolve.

**Recorded, not scored:** frame chosen; references found and how; per-stage harnesses; the link's design
and depth; pages read and never reached; tokens.
